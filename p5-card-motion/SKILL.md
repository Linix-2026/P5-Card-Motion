# p5-card-motion · p5.js 卡牌动效设计技能

把成熟卡牌游戏（Balatro / 杀戮尖塔 / Hearthstone 一脉）的动效沉淀为可拼装模块体系（M0–M15），支持零偏差复用、参数级个性化与跨引擎技巧蒸馏。面向 p5.js **2D Canvas**（1.11.0 实证，2.x 兼容标注）。

---

## 1. 触发条件（Trigger）与非触发（Non-trigger）

**应触发**（命中任一即调用）：
- 卡牌/手牌的悬停、拖拽换序、扇开、弧面排列、翻面、抽出/打出反馈；
- 卡面材质：镭射/全息覆膜、伪 3D 光泽与倾侧、多层投影、状态呼吸灯；
- 卡牌外围 UI juice：按钮三态反馈、屏幕震动、慢动作、命中闪烁/粒子；
- 用户给出 Unity/Godot/Blender 的卡牌或 UI 动效视频/链接，要求「用 p5.js 实现同样效果」；
- 评审、诊断、打磨已有卡牌动效的手感、性能、跨分辨率或可访问性；
- 明确点名本技能模块（M0–M15、镭射覆膜、弧面手牌、dampApproach、呼吸灯、打击感）。

**近邻负例（不要触发或须先澄清边界）**：

| 看似相关的请求 | 判定 | 处理 |
|---|---|---|
| WebGL 真 3D 场景/3D 粒子/体积光/3D shader | ❌ 非触发 | 本技能仅 2D Canvas；3D 倾斜是正交投影模拟 |
| 非卡牌、非交互反馈的生成艺术（流场/分形） | ❌ 非触发 | 走生成艺术类技能；仅 M1 数学内核可借用 |
| 纯战斗逻辑/数值/AI 设计（伤害公式、遗物效果） | ❌ 非触发 | 仅在动效需要消费其结果时，按 M0 注入点对接 |
| 只要静态卡面美术（无交互无动效） | ⚠️ 部分 | 可参考 M8 绘制，但不加载 M1–M7 |
| 非 p5 引擎（Phaser/原生 Canvas 框架）移植 | ⚠️ 转译 | 机制可参考，代码须按目标框架重写并明示 |

## 4. 分步操作指引（Step-by-step）

### 通用流程（每次任务都走）

1. **收集输入**：核对第 2 节清单；★项缺失先提问，其余缺省项在产出开头「假设」中声明。
2. **选模块**：查 08「〇、快速路由」表 → 确定必载/选配模块；需要卡牌先过 M0 契约核对字段与注入点。
3. **取代码**：从 08 对应模块节零偏差复制；M8 全量与实例模式写法取展厅 HTML；变换约定不清查 08「坐标系契约」表（**M7-a 在局部系内画、M7-b 自变换，混用是最高频事故**）。
4. **适配**：参数 → 层数 → 机制 三档递进；手感量（CARD_W/H、damp k、抽出幅度）不随画布缩放，布局量按 `W/1280` 等比换算。
5. **接管线**：实例模式 bind 别名 + 帧变量同步；ADD/HSB/矩阵栈复位；悬停命中每帧重算；两遍绘制与顶层纪律。
6. **自检验证**：过第 6 节质量门；浏览器缩放 75/110/150% 与最坏卡数组测；必要时启动本地 HTTP 服务让用户在浏览器实测。
7. **交付说明**：按第 5 节形态输出，标注所用模块、改动点、调参位置、降级行为。

### 按任务类型的配方

- **A. 做手牌悬停手感**：公共依赖 → M1 → M2 → M3 → M4（含输入端命中检测）→ 按预算加 M5/M6/M7 → M8 卡面。
- **B. 只要某一种材质/光效**（静态卡也可用）：公共依赖 → M8 画卡 → M7-b（自漂移）或 M12（呼吸灯）；不需要 M2/M4。
- **C. 拖拽换序（Balatro 式）**：M13 骨架（候选，先 A/B）+ M1/M2 + M3 布局，M5 拖拽深影、M7 tiltZ 相位增强；逻辑/视觉双轨是主干。
- **D. 战斗打击反馈**：M14（候选，先 A/B）挂场景根部；世界震屏只包世界层不包 UI；慢动作只乘 effDt 一处；触发走 fx 事件总线（M0 扩展）。
- **E. 新视频/新参考移植**：严格执行 09 五段式与提示词模板 → 先补转译对照表 → 骨架入 `视频蒸馏/` 并登记 09 队列 → 展厅 A/B 通过才入册 08。
- **F. 排查「手感不对/性能差」**：先问现象（跟手/回弹/残影/过曝/帧率），对照 08 自检清单 8 项定位；常见根因＝进出用了同一缓动、ADD 未复位、shadowBlur、每帧重掷随机量、命中未实时重算。

## 7. 硬约束速记（动效高频项；源项目完整 20 条）

1. 颜色统一 `cFill/cStroke` + RGB 查表，禁每帧 `fill('#hex')`；文字渲染前不描边。
2. ADD 用完复位 BLEND、HSB 用完回 RGB；矩阵/裁剪配平（drawCardVisual/drawRelicVisual 用 try/finally）。
3. 一切动画 deltaTime 驱动（`deltaTime || 16.67`）；damp k∈0.1–0.3。
4. 悬停命中每帧实时重算（1.12 倍 AABB、自右向左、弧面基线坐标）；移出画框立即清空。
5. 实例身份数字 `uid`（前缀 n）/ 召唤物 `_uid`（前缀 r）；浅拷贝新实例清 `_uid`；随机量掷签一次。
6. 子模块不硬编码父身份，语义经注入点传入；渲染模块不写游戏状态（走 fx 事件总线）。
7. 性能：光栅 200 块硬顶、粒子对象池、禁逐帧 shadowBlur；降级＝装饰先于反馈，交互位置反馈最后砍。

## 8. 边界与限制（Limitations）

- **仅 2D Canvas**：不提供 WebGL/真 3D 能力；伪 3D 是正交投影+光影模拟，不处理真实光照/遮挡/物理。
- **p5 版本**：成熟代码实证于 1.11.0；2.x 下矩阵/colorMode/blendMode 行为一致但 `drawingContext` 等 API **待复测**，使用时显式标注。
- **候选模块成熟度**：M9–M15 来自视频蒸馏，参数多为转译参考值（文档已标 `未验证`），未经展厅 A/B 不得作为实测结论交付；M10（视差）源视频无字幕，机制可信但细节必须人工看片核验。
- **不含素材管线**：不生成/不提供音频、图片、字体资源；音效只给 p5.sound 接法（需用户手势解锁 AudioContext）。
- **游戏语义外置**：canPlay、伤害结算、遗物/状态规则由宿主注入，技能内不编造玩法逻辑。
- **性能不打保票**：60fps 目标依赖设备；必须给品质档位与降级顺序，光栅/粒子设硬顶。
- **网络依赖**：默认 CDN（jsdmirror 国内镜像）；离线/发布场景应自托管 p5 库并说明。
- **文化与风格**：材质效果服务手感与信息，不做无意义特效堆叠（克制原则：一个震撼瞬间优于十个平庸叠加）。

## 9. 故障排查速查（Troubleshooting）

| 现象 | 首要怀疑 |
|---|---|
| 悬停进出一样「硬」 | 进出误用同一缓动（应 easeOutCubic / easeInCubic 非对称） |
| 卡移开后其他 UI 发白/过曝 | ADD 未复位 BLEND 或 HSB 未回 RGB |
| 隔空悬停/归位即被选中 | 命中未用弧面基线坐标实时重算；移出画框未清 hoveredCard |
| 复制牌/召唤牌动画联动 | 共享了 `_uid`；新实例未清字段 |
| 镭射/覆膜位置错位 | M7-a（局部系）与 M7-b（自变换）调用约定混用 |
| 浏览器缩放后手感变快/变慢 | 用了定帧 lerp 而非 dampApproach；或 canvasScale 未换算 |
| 帧率掉到个位数 | 逐帧 shadowBlur、光栅超 200、粒子无硬顶；按降级序先砍装饰层 |
| 单张手牌报错 | 除零未做 `Math.max(1,…)` 防御 |
