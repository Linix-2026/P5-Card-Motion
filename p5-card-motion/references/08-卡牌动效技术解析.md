## 一、三代演进总览

卡牌动效体系经历了三个阶段的演进，特性矩阵如下（✅ 完整实现 / 🔶 简化实现 / ❌ 无）：

| 特性 | V1.3 初版 | V2.0 过渡版（虚拟设计） | V2.1 最终版 |
|---|:---:|:---:|:---:|
| 手牌排列 | 直线平铺 | 弧面排列 | 弧面排列（曲率自适应） |
| 悬停缩放 | 瞬变 `scale(1.12)` | 阻尼插值 1→1.15 | 阻尼插值 1→1.18（非对称缓动） |
| 悬停抽出 | 瞬变 `-25px` | 阻尼 `-40px` | 阻尼 `-50px` |
| 随机微旋转 | ❌ | 有（静态） | 静态 ±3° + sin 漂移 |
| 动态阴影 | ❌ | 单层矩形 | 3 层柔影 + 1 层硬影（高度感知） |
| 伪 3D 透视倾斜 | ❌ | ❌ | 正交投影矩阵（≤18°）+ 方向阴影 |
| 3D 高光（受光面） | ❌ | ❌ | 渐变 sheen（顶部受光增强） |
| 镭射覆膜 | ❌ | 🔶 初代：自漂移多色粗斜线 | ✅ 鼠标驱动全息折射（光带+光栅+虹彩+噪点） |

| 性能防御 | ❌ | ❌ | NaN 钳制 / 像素块上限 / RGB 预转换 |

### M1 · 缓动内核（帧率无关阻尼 + 三种缓动曲线）

**来源**：L3613-3631。**依赖**：无。**被依赖**：M2/M3/M4/M5/M6 全部动效。

```js
// 缓动函数：easeOutCubic（先快后慢，用于悬停抽出——进入要"跟手"）
function easeOutCubic(t) { return 1 - Math.pow(1 - t, 3); }
// 缓动函数：easeInCubic（先慢后快，用于回弹归位——退出要"含蓄"）
function easeInCubic(t) { return t * t * t; }
// 缓动函数：easeOutQuad（先快后慢，用于 Tooltip 淡入）
function easeOutQuad(t) { return 1 - (1 - t) * (1 - t); }

// 帧率无关的阻尼插值：基于 deltaTime 逼近目标值
// k 为 60fps 基准下的逼近比例（0-1），值越大越快；dt 单位毫秒
// 演绎：factor = 1-(1-k)^(dt*60/1000)，把"每帧走 k"换算成"每毫秒走多少"
function dampApproach(current, target, k, dt) {
  let factor = 1 - Math.pow(1 - k, dt * 60 / 1000);
  return current + (target - current) * factor;
}
```

**参数表**：

| 参数 | 约定 | 出处 |
|---|---|---|
| `k` | **必须落在 0.1–0.3**（项目硬约束 #15）。悬停进度用 0.25，位移/缩放/旋转用 0.3 | 手牌管线全段 |
| `dt` | `deltaTime \|\| 16.67` 兜底（首帧 deltaTime 可能为 0/undefined） | L12107 |

**为什么这样写**：`lerp(current, target, 0.2)` 这类定步长插值在 144Hz 屏上会比 60Hz 快 2.4 倍——手感随帧率漂移。`dampApproach` 把 k 定义在 60fps 基准上，任何刷新率下收敛速度一致。这是整个动效体系的**手感锚点**。

**2.x 兼容**：纯数学，无 p5 依赖，任何版本可用。

### M2 · 动画状态管理（复合键 + 双轨身份）

**来源**：`getHandCardState` L11881-11898（实例版）、`getDeckCardState` L13104-13123（全局版）。

```js
// 每张手牌一份动画状态，字典按"卡牌实例身份"索引
// ⚠️ 键设计是本模块的核心：同 id 卡牌（如复制牌）必须各享独立动画态
let handCardStates = {}; // 挂在场景对象或全局命名空间下

function getHandCardState(card) {
  if (!card || !card.id)
    return { offsetY:0, scale:1, rotation:0, hoverProgress:0, microRot:0, microRotPhase:0 };
  // 双轨身份键：优先数字 uid（'n' 前缀，deck 实例），无数字 uid 时退回 _uid（'r' 前缀，召唤/复制实例）
  // 前缀分命名空间防互撞；_uid 惰性生成（首次访问时补发，写回卡牌对象）
  let instId = card.uid != null
    ? 'n' + card.uid
    : 'r' + (card._uid || (card._uid = Math.random().toString(36).substr(2, 6)));
  let key = card.id + '_' + instId;
  if (!handCardStates[key]) {
    handCardStates[key] = {
      offsetY: 0,        // 当前 Y 偏移（悬停抽出量）
      scale: 1,          // 当前缩放
      rotation: 0,       // 当前旋转角（弧度）
      hoverProgress: 0,  // 悬停进度 0-1（所有动效的统一驱动源）
      microRot: rand(-3, 3) * Math.PI / 180, // 随机微旋转（-3°~+3°，发牌时"掷签"一次并固定）
      microRotPhase: rand(0, Math.PI * 2),   // sin 漂移相位（避免所有卡同步摆动）
    };
  }
  return handCardStates[key];
}
```

**设计要点**：
1. **`hoverProgress` 是唯一驱动源**——位移/缩放/旋转全部从它派生（见 M4），而不是各自独立追目标。好处：悬停状态天然同步，不会出现"缩放到位了旋转还在转"的散架感。
2. **`microRot` 在创建时掷一次签**——每张卡获得固定的随机倾斜，`microRotPhase` 保证漂移错拍。若每帧重掷会高频抖动，观感是"卡牌在筛子里"。
3. **浅拷贝陷阱**（项目教训）：`{...card}` 浅拷贝会保留 `_uid`，导致原卡与拷贝卡共享动画态——所以键里必须带 `card.id`，且新造实例时要清 `_uid`。

**2.x 兼容**：纯数据逻辑，无 p5 依赖。

### M3 · 手牌弧面排列（布局数学）

**来源**：L12100-12114。只依赖 M1 的 `clamp/lerp`。

```js
// 手牌越多 → 间距越紧（>6 张时 580px 总宽硬约束），曲率越小
let spacing = totalCards > 6 ? Math.min(95, 580 / totalCards) : 110;
let startX = GAME_W * 0.5 - (totalCards - 1) * spacing / 2; // 居中起点
let baseY  = GAME_H * 0.78;
let arcHeight = clamp(40 - totalCards * 3, 10, 40); // 曲率：1张≈37px，6张≈22px，10张+→10px

// 第 i 张卡的弧面位置：centerOffset ∈ [-1, 1]，两端 -1/+1、中间 0
let centerOffset = (i - (totalCards - 1) / 2) / Math.max(1, (totalCards - 1) / 2);
let arcY = baseY - arcHeight * (1 - centerOffset * centerOffset); // 二次曲线：中间拱起，两端下探
let cx = startX + i * spacing;
// 弧线倾斜：两端卡牌向内倒（扇形感），>4 张时收窄到 0.12 rad 防挤
let arcRot = centerOffset * (totalCards > 4 ? 0.12 : 0.18);
```

**布局公式拆解**：
- `(1 - centerOffset²)` 是一条开口向下的抛物线：中间=1（拱满 `arcHeight`），两端=0（落回 `baseY`）。相比三角函数（`cos`）成本更低、形状更"挺"——底部弧线略平直，更符合卡牌游戏的"持握感"而非"圆桌感"。
- `arcRot` 与 `centerOffset` 线性相关，即卡牌沿弧线的法线方向倾倒，与 `arcY` 的抛物线叠加构成完整的"扇面"。
- **防御**：`Math.max(1, (totalCards-1)/2)` 防止单张手牌时除零（此时 centerOffset = -0.5 → 乘 2 后归位，也可直接特判 `totalCards===1`）。

**2.x 兼容**：纯数学。

### M4 · 悬停交互管线（两遍绘制 + 非对称缓动）

**来源**：`drawHand` L12095-12220。这是整套动效的**编排层**，串联 M1/M2/M3/M5/M6/M7。

**输入端 · 悬停命中检测**（来源 L8987-9010，M4 管线唯一的输入接口——没有它 `hoveredCard` 永远为 null）：

```js
// 悬停命中检测：每帧实时重算（硬约束 #16），禁止缓存上一帧命中结果
// 命中框 = 卡牌尺寸 × 1.12 的 AABB（宽容度补偿：命中用弧面基线坐标，不含悬停 offsetY）
// 自右向左遍历：右侧卡在两遍绘制中层级更高，优先命中
// ⚠️ 与下方编排层合并进同一作用域时，totalCards 只声明一次（此块产出的 cx/cy 为弧面基线坐标，
//    与编排层第一遍的布局计算同源——宿主可先算布局存数组，命中与绘制共用，避免每帧算两遍）
this.hoveredCard = null;
let totalCards = cs.hand.length;
if (totalCards > 0) {
  let spacing = totalCards > 6 ? Math.min(95, 580 / totalCards) : 110;
  let startX = GAME_W * 0.5 - (totalCards - 1) * spacing / 2;
  let baseY = GAME_H * 0.78;
  let arcHeight = clamp(40 - totalCards * 3, 10, 40);
  for (let i = totalCards - 1; i >= 0; i--) {
    let card = cs.hand[i];
    let centerOffset = (i - (totalCards - 1) / 2) / Math.max(1, (totalCards - 1) / 2);
    let arcY = baseY - arcHeight * (1 - centerOffset * centerOffset);
    let cx = startX + i * spacing;
    let cy = arcY;
    let hoverW = CARD_W * 1.12;
    let hoverH = CARD_H * 1.12;
    if (mx() > cx - hoverW / 2 && mx() < cx + hoverW / 2 &&
        my() > cy - hoverH / 2 && my() < cy + hoverH / 2) {
      this.hoveredCard = card;
      break;
    }
  }
}
```

```js
for (let i = 0; i < totalCards; i++) {
  let card = cs.hand[i];
  if (card === hoveredCard) continue;          // 悬停卡跳过，留给第二遍

  let state = this.getHandCardState(card);
  let dt = deltaTime || 16.67;

  // ① 悬停进度：未悬停 → 回归 0，k=0.25
  state.hoverProgress = dampApproach(state.hoverProgress, 0, 0.25, dt);
  // ② 关键设计：退出动画用 easeInCubic（先慢后快）——抽出的卡"含蓄地"滑回去
  let hoverEase = easeInCubic(state.hoverProgress);

  // ③ 位移/缩放/旋转全部由 hoverEase 派生，各自再过一层 dampApproach 做二级平滑
  state.offsetY  = dampApproach(state.offsetY,  -50 * hoverEase, 0.3, dt);
  state.scale    = dampApproach(state.scale,    1 + 0.18 * hoverEase, 0.3, dt);
  // 旋转 = 弧线倾角 + 固定微旋转 + sin 漂移；悬停时 lerp 归零
  let microDrift = Math.sin(frameCount * 0.02 + state.microRotPhase) * 0.02;
  let targetRot  = lerp(arcRot + state.microRot + microDrift, 0, hoverEase);
  state.rotation = dampApproach(state.rotation, targetRot, 0.3, dt);

  // ④ 阴影先画（垫底），再画卡牌本体
  this.drawCardShadow(cx, cy, Math.abs(state.offsetY), state.scale, state.rotation);
  push();
  translate(cx, cy + state.offsetY);
  rotate(state.rotation);
  scale(state.scale);
  drawCardVisual(card, 0, 0, 1);               // M8 卡牌本体
  if (isSpecialCard(card)) drawCardLaser(1, cx, cy + state.offsetY, state.rotation, false); // M7
  if (!canPlay) { fill(0,100); noStroke(); rect(-CARD_W/2, -CARD_H/2, CARD_W, CARD_H, 10); }
  pop();
}

// ---- 第二遍：绘制悬停卡（最高渲染层——项目硬约束 #12）----
if (hoveredCard) {
  // ... 同款布局计算（用 idx 而非 i）...
  let state = this.getHandCardState(hoveredCard);
  // ① 悬停进度 → 1，k=0.25
  state.hoverProgress = dampApproach(state.hoverProgress, 1, 0.25, dt);
  // ② 关键设计：进入动画用 easeOutCubic（先快后慢）——抽出要"跟手"
  let hoverEase = easeOutCubic(state.hoverProgress);
  // ③ 同款派生（略）...
  state.rotation = dampApproach(state.rotation, 0, 0.3, dt); // 悬停时旋转完全归零

  // ④ 3D 倾斜：鼠标相对卡心位置 → 倾角 + 方向阴影偏移（M6）
  let tilt = computeCardTilt(cx, cy + state.offsetY, state.scale, hoverEase);
  this.drawCardShadow(cx + tilt.shadowOffX, cy + tilt.shadowOffY,
                      Math.abs(state.offsetY), state.scale, state.rotation);
  push();
  translate(cx, cy + state.offsetY);
  rotate(state.rotation);
  scale(state.scale);
  applyCardTilt3D(tilt.tiltX, tilt.tiltY);     // ⑤ 刚体投影（M6）
  drawCardVisual(hoveredCard, 0, 0, 1);
  applyCardSheen3D(hoverEase, tilt.tiltX, tilt.tiltY); // ⑥ 受光高光（M6）
  if (isSpecialCard(hoveredCard)) drawCardLaser(1, cx, cy + state.offsetY, state.rotation, true);
  if (canPlay) {                               // ⑦ 可打金框（外扩 3px）
    noFill(); cStroke('goldBright'); strokeWeight(2);
    rect(-CARD_W/2-3, -CARD_H/2-3, CARD_W+6, CARD_H+6, 8);
  }
  pop();
}
```

**非对称缓动是手感的核心**：
- **进入**用 `easeOutCubic`（先快后慢）：鼠标一碰到卡牌立即响应大位移，"跟手"；
- **退出**用 `easeInCubic`（先慢后快）：卡牌离开悬停时先迟疑再滑落，像被指尖"放走"。
- 同一个 `hoverProgress`、同一组 `dampApproach` 参数，仅靠缓动方向区分进出，是整套手感最廉价也最有效的技巧。

**两遍绘制的原因**：悬停卡放大后必然遮住邻卡，若按索引顺序绘制，手牌右端的悬停卡会被更右的邻卡反遮。第一遍画全部非悬停卡，第二遍把悬停卡重画在顶层——这是 2D 即时模式渲染下的标准 z-order 手法（对应硬约束 #12）。

**性能防御**（生产代码 L12773-12774）：`dampApproach` 传入 NaN 会永久污染状态，所以网格管线对 hoverProgress 做了钳制：
```js
if (isNaN(state.hoverProgress) || state.hoverProgress < 0) state.hoverProgress = 0;
if (state.hoverProgress > 1) state.hoverProgress = 1;
```

### M5 · 动态多层阴影（高度感知）

**来源**：`drawCardShadow` L11909-11940（实例版）/ `drawCardShadowGlobal` L13137-13160（全局版，代码相同）。

```js
// 多层矩形阴影：远层模拟模糊扩散，近层硬阴影贴合
// x,y 为卡牌中心（未含 offsetY 前的弧面位置）；liftAmount = 悬浮高度
function drawCardShadow(x, y, liftAmount, cardScale, rotation) {
  push();
  noStroke();
  let s = cardScale || 1, rot = rotation || 0;
  let liftFactor = clamp(liftAmount / 50, 0, 1);   // 悬浮高度归一化 [0,1]（-50px 抽出 → 满格）
  let shadowScale = 1 + liftFactor * 0.05;          // 悬得越高影子越大（1.0→1.05，模拟光源近距离扩散）
  let baseAlpha = 60 - liftFactor * 20;             // 悬得越高影子越淡（60→40，模拟光强分散）
  translate(x, y);
  rotate(rot);                                      // 阴影跟随卡牌旋转，保持形状一致
  scale(s * shadowScale);
  // 三层柔影：偏移与透明度递减，远层更偏更淡 → 人眼自动脑补成"高斯模糊"
  let layers = [
    { offX: 8 + liftFactor*4, offY: 16 + liftFactor*8, alpha: 15 - liftFactor*5 },
    { offX: 6 + liftFactor*3, offY: 12 + liftFactor*6, alpha: 25 - liftFactor*8 },
    { offX: 4 + liftFactor*2, offY:  8 + liftFactor*4, alpha: 40 - liftFactor*10 },
  ];
  layers.forEach(L => { fill(0, Math.max(5, L.alpha));
    rect(-CARD_W/2 + L.offX, -CARD_H/2 + L.offY, CARD_W, CARD_H, 10); });
  // 近层硬阴影：偏移(2,4)——默认光从左上来
  fill(0, baseAlpha);
  rect(-CARD_W/2 + 2, -CARD_H/2 + 4, CARD_W, CARD_H, 10);
  pop();
}
```

**为什么用 4 层矩形而不是 `drawingContext.shadowBlur`**：Canvas 原生 shadowBlur 每次绘制都要对整卡做高斯卷积，手牌 + 网格 + 战斗同时刷新时是显著热点；分层矩形把模糊量化成 3 层，GPU 合成代价趋近于零，暗底场景下视觉差异 <5%。**这是"60fps 意境连贯"优先的典型取舍**。

**阴影的方向性**：硬影固定偏移 `(2,4)` 表示默认光源在左上；悬停时 `computeCardTilt` 返回的 `shadowOffX/Y` 会把整体阴影推向卡牌倾斜的反方向（M6），形成"卡牌朝鼠标倾、影子往反处逃"的物理暗示。

**2.x 兼容**：`fill/rect` 基础 API，无差异。

### M6 · 伪 3D 透视倾斜三件套（刚体投影 + 受光高光）

**来源**：L16911-16957。**这是整个动效体系技术含量最高的一组**：在 2D Canvas 上以正交投影模拟 3D 刚体旋转，无 WebGL、无 3D 库。

```js
// ---- ① 倾角计算：鼠标相对卡心位置 → 绕 X/Y 轴倾角 + 方向阴影偏移 ----
// ccx,ccy 为卡牌当前屏幕中心（含 offsetY/scale）；hoverEase 保证倾斜只发生在悬停时
function computeCardTilt(ccx, ccy, cardScale, hoverEase) {
  const MAX_TILT = 0.32; // ~18°——手测上限：再大卡面文字开始难以阅读
  let halfW = Math.max(1, (CARD_W * (cardScale || 1)) / 2);  // 防除零
  let halfH = Math.max(1, (CARD_H * (cardScale || 1)) / 2);
  let dx = clamp((mx() - ccx) / halfW, -1, 1);   // -1..1，正=鼠标在卡右侧
  let dy = clamp((my() - ccy) / halfH, -1, 1);   // -1..1，正=鼠标在卡下侧
  let tiltX = -dy * MAX_TILT * hoverEase;        // 鼠标在下 → 顶边向前倒（低头看）
  let tiltY =  dx * MAX_TILT * hoverEase;        // 鼠标在右 → 右边向后倒（迎向鼠标）
  // 阴影方向：光从上前方来，卡牌倾向鼠标 → 阴影落向反方向
  let shadowOffX = -dx * 16 * hoverEase;
  let shadowOffY = -dy *  8 * hoverEase;
  return { tiltX, tiltY, shadowOffX, shadowOffY };
}

// ---- ② 刚体投影矩阵：R = Ry(tiltY)·Rx(tiltX) 取 (x,y) 屏幕投影 ----
// 推导：先绕 X 轴转（tiltX）再绕 Y 轴转（tiltY），3D 点 (x,y,z=0) 投影到 z=0 平面：
//   x' = cos(tiltY)·x + sin(tiltX)·sin(tiltY)·y
//   y' = cos(tiltX)·y
// 这是物理正确的刚体旋转正交投影，而非"顶边压扁 + 底边拉长"的假透视
function applyCardTilt3D(tiltX, tiltY) {
  let cosY = Math.cos(tiltY), sinY = Math.sin(tiltY);
  let cosX = Math.cos(tiltX), sinX = Math.sin(tiltX);
  // p5 applyMatrix(a,b,c,d,e,f): x'=a·x+c·y+e, y'=b·x+d·y+f
  applyMatrix(cosY, 0, sinX * sinY, cosX, 0, 0);
}

// ---- ③ 受光高光：倾斜时朝光边缘加一道渐变 sheen ----
// 顶部受光（顶边向前倾时增强），底部反向压暗 → 立体感的关键补笔
function applyCardSheen3D(strength, tiltX, tiltY) {
  if (strength < 0.05) return;               // 强度过低直接跳过，省一次 save/restore
  let ctx = drawingContext;                  // 原生 Canvas 2D 上下文（p5 全部版本可用）
  ctx.save();                                // 状态隔离：不污染 p5 绘图状态
  let topLight = clamp(-tiltX / 0.32, 0, 1) * 0.5 + 0.5; // 前倾（tiltX<0）越深顶光越强
  let a = 70 * strength * topLight;
  // 三段线性渐变：顶部白高光 → 35% 处消失 → 底部黑阴影
  let grad = ctx.createLinearGradient(0, -CARD_H/2, 0, CARD_H/2);
  grad.addColorStop(0,    'rgba(255,255,255,' + (a / 255).toFixed(3) + ')');
  grad.addColorStop(0.35, 'rgba(255,255,255,0)');
  grad.addColorStop(1,    'rgba(0,0,0,'      + (40 * strength / 255).toFixed(3) + ')');
  ctx.fillStyle = grad;
  // 圆角裁剪到卡面，防止高光溢出边框
  ctx.beginPath();
  if (ctx.roundRect) ctx.roundRect(-CARD_W/2, -CARD_H/2, CARD_W, CARD_H, 10);
  else ctx.rect(-CARD_W/2, -CARD_H/2, CARD_W, CARD_H);
  ctx.fill();
  ctx.restore();
}
```

**矩阵推导细节**（为什么 6 参数能表达 3D 旋转）：
2D Canvas 仿射矩阵 `applyMatrix(a,b,c,d,e,f)` 对点 `(x,y)` 的变换为 `x'=a·x+c·y+e, y'=b·x+d·y+f`。将 3D 旋转 `R = Ry·Rx` 作用在 `z=0` 的平面上并丢弃 z 分量，得到的恰是一个 2×2 线性映射——`a=cosY`（Y 轴旋转把水平方向压缩，模拟"侧转"），`c=sinX·sinY`（两轴旋转的耦合项，模拟"斜俯视"），`d=cosX`（X 轴旋转把垂直方向压缩，模拟"前倾"）。**无需 WebGL 即可得到物理正确的透视暗示**，且与后续 `rect/ellipse/text` 完全兼容（它们都被同一矩阵变换）。

**调用时序（严格）**：`translate → rotate → scale → applyCardTilt3D → drawCardVisual → applyCardSheen3D`。sheen 必须在卡面绘制**之后**叠加；tilt 必须在卡面绘制**之前**施加，否则文字不随卡面变形。

**2.x 兼容实证**：`index220(2.x).html`（p5 2.3.3）L16978-17004 原样保留这三个函数，唯一改动是项目内部 `clamp→clampNum` 重命名。`applyMatrix` 六参数 2D 形式与 `drawingContext` 在 2.x 均无破坏性变更。

### M7 · 镭射覆膜（全息材质，双版本）

**来源**：战斗版 `drawCardLaser` L11942-12025（鼠标驱动全量版）；网格版 `drawCardLaserGlobal` L13163-13205（非交互简化版）。

#### M7-a · 全量版（鼠标驱动全息折射）

```js
// 前提：调用方已在卡牌局部坐标系（translate/rotate/scale 之后）或传入卡牌屏幕参数
// cardScale/cardCx/cardCy/cardRotation 用于把屏幕鼠标逆变换回卡牌局部坐标
function drawCardLaser(cardScale, cardCx, cardCy, cardRotation, isHovered) {
  push();
  blendMode(ADD);            // 加法混合：暗底上做"发光材质"的唯一正解（用完必须复位！）
  noStroke();
  let s = cardScale || 1;
  // 色相循环：悬停 2 倍速（1.0 vs 0.5 度/帧）——动静状态的呼吸差
  let hueSpeed = isHovered ? 1.0 : 0.5;
  let baseHue = (frameCount * hueSpeed) % 360;
  let brightBoost = isHovered ? 1.3 : 1.0;   // 悬停亮度 +30%

  // === 鼠标逆变换：屏幕坐标 → 卡牌局部坐标（抵消平移与旋转）===
  let dx = mx() - cardCx, dy = my() - cardCy;
  let cosR = Math.cos(-cardRotation), sinR = Math.sin(-cardRotation);
  let localMx = dx * cosR - dy * sinR;
  let localMy = dx * sinR + dy * cosR;
  let mouseNormX = clamp(localMx / (CARD_W * s / 2), -1, 1);
  let mouseNormY = clamp(localMy / (CARD_H * s / 2), -1, 1);

  // === 1. 对角线全息光带：位置由鼠标投影驱动 ===
  let bandWidth = isHovered ? 20 : 13;
  let bandPos = (mouseNormX + mouseNormY) * 0.5;          // 鼠标沿对角线方向投影 [-1,1]
  let cardW = CARD_W * s, cardH = CARD_H * s;
  let bandCenter = bandPos * (cardW + cardH) * 0.25;

  colorMode(HSB, 360, 100, 100, 100);        // 切 HSB：材质色相操作的自然空间
  let pixCount = 0;

  // === 2. 像素光栅衍射：4px 方块沿对角线排布，模拟全息膜的颗粒折射 ===
  let pixSize = 4, gap = 1;
  for (let py = -cardH/2; py < cardH/2; py += pixSize + gap) {
    for (let px = -cardW/2; px < cardW/2; px += pixSize + gap) {
      let proj = (px + py) * 0.5;                       // 沿对角线投影
      let perpDist = (px - py) * 0.707;                 // 到对角线的垂直距离
      let distToBand = Math.abs(perpDist - bandCenter);
      if (distToBand > bandWidth) continue;             // 光带外不画（省 fill 调用）
      let bandAlpha = (1 - distToBand / bandWidth) * 60 * brightBoost; // 中心最强
      // 色相 = 基准 + Perlin 噪声扰动(±30) + 沿带渐变 + 时间漂移
      let hueOffset = noise(px * 0.1, py * 0.1, frameCount * 0.01) * 30;
      let lengthHue = (proj * 0.5 + frameCount * hueSpeed * 0.3) % 360;
      fill((baseHue + hueOffset + lengthHue) % 360, 70, 90 * brightBoost, bandAlpha);
      rect(px, py, pixSize, pixSize);
      if (++pixCount >= 200) break;                     // ★ 性能硬顶：200 块封顶
    }
    if (pixCount >= 200) break;
  }

  // === 3. 边缘虹彩描边：2 层互补色相，鼠标距离调制 ===
  let mouseDist = Math.sqrt(mouseNormX*mouseNormX + mouseNormY*mouseNormY);
  let edgeHue = (baseHue + mouseDist * 60) % 360;
  noFill();
  for (let i = 0; i < 2; i++) {
    stroke((edgeHue + i * 60) % 360, 80, 100, 40 + Math.sin(frameCount*0.05 + i) * 20);
    strokeWeight(2);
    rect(-cardW/2 + i, -cardH/2 + i, cardW - i*2, cardH - i*2, 10 - i);
  }

  // === 4. 噪点纹理：40 颗 2px 彩噪，Perlin 漂移（覆膜的"磨砂感"）===
  noStroke();
  let noiseOffset = frameCount * 0.5;
  for (let i = 0; i < 40; i++) {
    let nx = noise(i * 0.3,     noiseOffset * 0.01) * cardW - cardW/2;
    let ny = noise(i * 0.3 + 100, noiseOffset * 0.01) * cardH - cardH/2;
    let na = 15 + noise(i * 0.5, noiseOffset * 0.02) * 10;
    fill((baseHue + i * 10) % 360, 50, 100, na);
    rect(nx, ny, 2, 2);
  }

  colorMode(RGB, 255);
  blendMode(BLEND);          // ★ 硬约束 #5：ADD 用完必复位，否则后续一切绘制过曝
  pop();
}
```

**材质设计四层拆解**（从下到上）：

| 层 | 视觉职能 | 驱动源 | 成本控制 |
|---|---|---|---|
| 对角光带（光栅实现） | 全息膜的主折射面 | **鼠标位置**（对角投影） | 只画带内像素，200 块硬顶 |
| 边缘虹彩 | 膜的边缘散射 | 鼠标距卡心距离 | 仅 2 个描边矩形 |
| 噪点纹理 | 磨砂颗粒感 | Perlin 三维噪声（时间维漂移） | 固定 40 颗 |
| 色相循环 | "活着的材质" | frameCount（悬停 2 倍速） | 0 |

**核心思想——鼠标驱动的折射**：真实镭射膜的虹彩随视角变化。这里用"鼠标相对卡牌的归一化位置"代理"视角"：光带位置 `bandPos = (mouseNormX + mouseNormY) * 0.5` 让光带沿对角线追随鼠标扫过卡面，边缘虹彩色相随鼠标距卡心远近偏移 ±60°——**卡面像一个被指尖倾斜的水晶棱镜**。逆变换（旋转矩阵 `-cardRotation`）保证卡牌即使在弧面上倾斜时，光带依然贴着卡面几何而非屏幕几何。

#### M7-b · 简化版（网格场景非交互）

```js
// 网格/奖励/商店等非战斗场景：无逐帧鼠标语义 → 光带用 sin 自漂移，砍掉噪点层
function drawCardLaserGlobal(cardScale, cardCx, cardCy, cardRotation, isHovered) {
  push();
  translate(cardCx, cardCy);
  rotate(cardRotation || 0);
  blendMode(ADD);
  noStroke();

  let baseHue = (frameCount * hueSpeed) % 360;
  let brightBoost = isHovered ? 1.3 : 1.0;
```

**镭射资格判定**（`isSpecialCard` L11900-11907）：`upgraded === true` / 关键词含「先攻|流转|震慑|异常」/ `rarity === 'rare'` 三者其一。**稀缺性即高级感**——镭射只在升级与稀有卡上出现，升级 Tooltip（L13250-13254）还会以色相循环文字明示「升级后获得镭射覆膜特效」，把材质变成成长激励。

## 三、虚拟过渡版 V2.0 的设计推导（skill 个性化修改示范）

V2.0 不存在于任何历史文件中——它是为展示演进叙事而**设计的中间形态**，同时充当「基于 V2.1 成熟模块做个性化裁剪」的完整示范。设计目标：比 V1.3 流畅（引入阻尼内核），比 V2.1 简陋（无 3D / 简化镭射）。

**取材决策表**（每个决策都回答"为什么"）：

| 维度 | 决策 | 理由 |
|---|---|---|
| 排列 | 采用 M3 弧面 | V1.3→V2.1 布局的分水岭就是弧面，必须在这代引入 |
| 悬停 | `dampApproach` k=0.25，进出**同用** easeOutCubic，scale 1.15 / offsetY -40 | 有阻尼但无非对称缓动——保留与 V2.1 的可感知差距（退出更"黏"） |
| 微旋转 | 保留静态 `microRot`，**砍掉** sin 漂移 | 呈现"漂移是 V2.1 才补上的呼吸感"这一演进细节 |
| 阴影 | 单层矩形（alpha 55，偏移 2,4），无高度感知 | M5 的四层是精修项，过渡版够用即可 |
| 3D 倾斜 / sheen | 完全移除 | 这套是 V2.1 后期（T194 一代）才沉淀的重武器 |
| 镭射 | 自制「初代覆膜」：3 根自漂移多色粗斜线（clip 到卡面内）凑出一条光带，无鼠标驱动、无像素光栅、无噪点、无虹彩边 | 叙事定位：**未抓取/参考网络成熟方案**，仅凭直觉实现的升级；hover 时仅多加两根线，演示"成熟材质出现之前有多朴素" |

V2.0 悬停管线（完整实现，可直接复用）：

```js
// V2.0：阻尼悬停 + 弧面 + 静态微旋转 + 单层阴影 + 初代镭射
function updateAndDrawV2Card(card, cx, cy, arcRot, hovered, state, dt) {
  // ① 悬停进度：与 V2.1 同款 dampApproach，但缓动不分进出
  state.hoverProgress = dampApproach(state.hoverProgress, hovered ? 1 : 0, 0.25, dt);
  let hoverEase = easeOutCubic(state.hoverProgress);           // ← 进出同用，退出会偏"急"
  // ② 派生动效：幅度略小于 V2.1（-40 / 1.15 vs -50 / 1.18）
  state.offsetY  = dampApproach(state.offsetY,  -40 * hoverEase, 0.3, dt);
  state.scale    = dampApproach(state.scale,    1 + 0.15 * hoverEase, 0.3, dt);
  // ③ 旋转：弧面倾角 + 静态微旋转（无 sin 漂移）；悬停归零
  let targetRot = lerp(arcRot + state.microRot, 0, hoverEase);
  state.rotation = dampApproach(state.rotation, targetRot, 0.3, dt);

  // ④ 单层阴影（无高度感知）
  push(); noStroke();
  translate(cx, cy); rotate(state.rotation); scale(state.scale);
  fill(0, 55);
  rect(-CARD_W/2 + 2, -CARD_H/2 + 4, CARD_W, CARD_H, 10);
  pop();

  // ⑤ 本体 + 初代镭射
  push();
  translate(cx, cy + state.offsetY);
  rotate(state.rotation);
  scale(state.scale);
  drawCardVisual(card, 0, 0, 1);
  pop();
  if (isSpecialCard(card)) drawLaserV2(state.scale, cx, cy + state.offsetY, state.rotation, hovered);
  if (hovered && canPlay(card)) {
    noFill(); cStroke('goldBright'); strokeWeight(2);
    rect(cx - CARD_W/2*state.scale - 3, cy + state.offsetY - CARD_H/2*state.scale - 3,
         CARD_W*state.scale + 6, CARD_H*state.scale + 6, 8);
  }
}

// 初代镭射：自漂移多色粗斜线「凑」出一条光带
// （未参考网络成熟方案的朴素直觉：无像素光栅/无鼠标驱动/无噪点/无虹彩边；hover 仅多加两根线）
function drawLaserV2(cardScale, cx, cy, rotation, isHovered) {
  push();
  translate(cx, cy); rotate(rotation || 0); scale(cardScale || 1);
  blendMode(ADD);
  // 粗斜线两端超长 → 裁剪到圆角卡面内（朴素实现唯一的几何处理）
  let ctx = drawingContext;
  ctx.save();
  ctx.beginPath();
  if (ctx.roundRect) ctx.roundRect(-CARD_W/2, -CARD_H/2, CARD_W, CARD_H, 10);
  else ctx.rect(-CARD_W/2, -CARD_H/2, CARD_W, CARD_H);
  ctx.clip();
  colorMode(HSB, 360, 100, 100, 100);
  let lineCount = isHovered ? 5 : 3;                       // 平时 3 根，悬停 5 根
  let L = CARD_W + CARD_H;                                 // 线段半长，超出交裁剪
  let drift = Math.sin(frameCount * 0.015) * (CARD_W + CARD_H) * 0.22; // 整组自漂移，不跟鼠标
  for (let i = 0; i < lineCount; i++) {
    let t = (i - (lineCount - 1) / 2) / ((lineCount - 1) / 2);          // -1..1
    let off = drift + t * 24;                                            // 沿法线排开
    let hue = (frameCount * 0.8 + i * (360 / lineCount)) % 360;         // 每根线各自变色（多色）
    let a = (isHovered ? 58 : 38) * (1 - 0.5 * Math.abs(t));            // 中线亮、两侧衰减
    stroke(hue, 65, isHovered ? 100 : 90, a);
    strokeWeight(11);
    let nx = off * 0.707, ny = -off * 0.707;                            // 法线 (1,-1)/√2
    line(-L + nx, -L + ny, L + nx, L + ny);
  }
  ctx.restore();
  colorMode(RGB, 255);
  blendMode(BLEND);
  pop();
}
```

> **skill 修改指引**：个性化改动优先动**参数**（幅度/速度/缓动曲线），其次动**层数**（镭射四层取几层、阴影几层），最后才动**机制**（如把光带驱动源从鼠标换成噪声）。三者难度递增、风险递增。所有模块的状态字段结构保持不变（M2），即可无痛并入 V2.1 完整管线。

**向上扩展示范：给 M7-a 加第 5 层「全息水印」**（演示"向上长肉"的标准姿势）：


## 四、工程约束与性能预算（动效专项）

以下为项目 20 条硬约束中与卡牌动效直接相关的子集（完整版见 `06-工程规范与硬约束20条.md`）：

| # | 约束 | 动效场景中的意义 |
|---|---|---|
| #4 | 统一 `cFill/cStroke`，禁 `fill('#hex')` | p5 字符串色解析是每帧热点；暗色系手绘风格下色值集中管理也保风格一致 |
| #5 | `blendMode(ADD)` 后必须复位 `BLEND` | 镭射/粒子忘复位 → 全画布后续绘制过曝（幽灵 bug 之王） |
| #7 | `drawCardVisual` 必须 try/finally 包 push/pop | 一张坏卡泄漏矩阵栈 → 整画布变换永久漂移 |
| #12 | 悬停卡渲染在最高层 | 两遍绘制模式（M4） |
| #15 | 动画一律 `dampApproach(a,b,k,dt)`，k∈0.1–0.3 | 帧率无关手感；k>0.3 会从"阻尼"劣化为"弹簧抖动" |
| #17 | 字段必须确认被引用 | 动画状态六字段全部被消费，禁止僵尸字段占内存 |

**性能预算实测要点**（19778 行基线）：
- 镭射光栅 **200 块硬顶**（L11994）——全手牌 6 张全特殊卡时最坏 1200 rect/帧，实测仍稳 60fps；
- 网格场景开启**视口剔除**（L18790：滚动出视口的卡跳过全部矩阵运算）；
- 阴影用分层矩形替代 shadowBlur（M5，理由见该节）；
- 颜色查表预转换（M8，理由见该节）；
- `dt` 兜底 `deltaTime || 16.67`，NaN 双重钳制（M4）。

**动效降级与可访问性钩子**（`prefers-reduced-motion` 及低端设备）：

```js
// 挂载于宿主 setup：一次检测，全局生效
const REDUCE_MOTION = typeof window.matchMedia === 'function'
  && window.matchMedia('(prefers-reduced-motion: reduce)').matches;

// 消费方式：只动参数，不动模块结构（改动量最小，且可随时回退）
// M4  悬停 k：0.25/0.3 → 0.9（阻尼近似"直接吸附"，保留位移反馈、去掉滑行过程）
// M4  microDrift 幅度 → 0（sin 呼吸漂移是纯装饰，首砍）
// M7  hueSpeed → 0 且跳过第 3/4 层（虹彩/噪点静止化）；光带跟随鼠标保留——那是交互反馈

```

**降级顺序＝装饰先于反馈**：呼吸漂移 → 色相循环 → 虹彩/噪点 → 阴影层数 → 缓动吸附化。交互位置反馈（金框、抽出位移、光带跟随鼠标）保留到最后——它们是"信息"不是"动效"。

**接入后自检清单**（逐项过，全部 ✓ 才算接完）：
- [ ] 悬停进入"跟手"（easeOutCubic 先快后慢）、退出有"放走"感（easeInCubic）——两头都急 = 进出误用了同一缓动
- [ ] 快速在卡间横移 10 次：无残影、无卡死——两遍绘制与 hoverProgress 钳制正常
- [ ] 镭射卡移开后，后续绘制的 UI 无过曝——`blendMode(BLEND)` 复位到位（幽灵 bug 之王）
- [ ] 浏览器缩放 75%/110%/150% 手感一致——dampApproach 帧率无关 + `canvasScale` 换算正确
- [ ] 复制牌/召唤牌的悬停动画相互独立——M2 双轨键未共享 `_uid`
- [ ] 仅 1 张手牌不报错——M3 的 `Math.max(1, …)` 除零防御生效
- [ ] 构造一张缺 `name/desc` 的坏卡：不炸画布、后续卡照常绘制——M8 try/finally 矩阵栈平衡
- [ ] 60fps 基线：6 张全特殊卡最坏 1200 rect/帧（光栅 200 硬顶），低于 55fps 先查每帧 fill 调用数

**坐标系契约**（最常见的踩错点——哪些函数自建变换、哪些假定局部系）：

| 函数 | 变换约定 | 调用方式 |
|---|---|---|
| `drawCardVisual` | 假定调用方已建立**局部系**（translate/rotate/scale 之后） | `drawCardVisual(card, 0, 0, 1)` |
| `applyCardTilt3D` / `applyCardSheen3D` | 局部系内施加，时序严格（卡面之前 / 之后，见 M6） | 传倾角参数 |
| `drawCardShadow` | **自建变换**（内部 translate/rotate/scale） | 传屏幕坐标 `(cx, cy, lift, scale, rot)` |
| `drawCardLaser`（M7-a 全量版） | **不自建平移/旋转**——需卡牌屏幕参数做鼠标逆变换 | 在局部系内调用，传 `(scale, cx, cy, rot, hovered)` |
| `drawCardLaserGlobal`（M7-b 简化版） | **自建 translate/rotate** | 传卡心屏幕坐标 |
| `drawLaserV2`（V2.0） | 自建变换 + 圆角裁剪 | 传卡心屏幕坐标 |

⚠️ **M7-a 与 M7-b 的变换约定不同**（全量版在局部系内画、简化版自变换）——混用会让覆膜错位一个卡心偏移，这是移植时最高频的事故点。

**注入点与数据入口**：宿主必须提供的最小集合（`hoveredCard / canPlay / getEffectiveStatusAmt / cs / gs.hasRelic / mx-my`）已在 M0「卡牌数据契约与宿主注入点」收敛成表。

**实例模式适配**：本手册代码按 p5 全局模式书写（裸用 `mouseX/deltaTime/frameCount/drawingContext`）。实例模式工程两种接法：
1. **bind 别名法**（推荐，展厅 `卡牌动效演进展厅.html` 即此写法）：把用到的 p5 方法 `p[n].bind(p)` 成短名，每帧从实例同步帧变量（`frameCount = p.frameCount; deltaTime = p.deltaTime; drawingContext = p.drawingContext`），成熟代码近乎逐行移植，改动量最小；
2. **显式传参法**：给每个模块加 ctx 参数——侵入性大，仅在严禁模块级可变状态的项目采用。

**分辨率迁移配方**：M3/M4 的 `580px` 总宽、`GAME_H*0.78` 基线、`110px` 间距均为 1280×720 设计基准值。换画布尺寸时按 `scale = W / 1280` 等比缩放这组布局基准值（鼠标读取侧只需设 `canvasScale`，见公共依赖块），而卡牌尺寸 `CARD_W/H` 与手感参数（damp k、抽出幅度）**不必跟随缩放**——它们是"手感量"不是"布局量"。

**悬停判定**一律**每帧实时重算**（硬约束 #16），禁止缓存上一帧命中结果。
