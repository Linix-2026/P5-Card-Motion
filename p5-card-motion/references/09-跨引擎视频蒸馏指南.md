# 09 · 跨引擎视频蒸馏指南（Unity/Godot → p5.js 动效能力增强）

> **交付级别：L2（skill 迭代支持 / 方法论文档）**
>
> **定位**：本文件是 skill 的**长期迭代基础设施**——规定如何从 Unity/Godot 生态的动效视频中提取「设计语言 + 实现机制」，转译为 p5.js 2D Canvas 惯用法，并**并入**现有 reference（`08-卡牌动效技术解析.md` 的 M0–M8 模块体系），而不是另起炉灶。
>
> **读者**：① 调用 skill 的智能体（执行蒸馏时必须遵守第三/四/五节的硬性规范）；② 维护 skill 的人（第七/八/九节是操作流程）。

---

## 一、为什么值得蒸（价值判定）

卡牌/Board-game 动效属于 **2D UI 动效，是跨引擎迁移成本最低的品类之一**（远低于 3D 粒子、体积光）。价值按层判定：

| 层 | 共通性 | 对 p5 skill 的价值 | 蒸馏取舍 |
|---|:---:|---|---|
| **设计语言**（节奏、非对称缓动、juice、稀缺性→高级感、两遍置顶、预期/跟随） | ≈100% 引擎无关 | **最高**——正是 08 文档「为什么这样写」层的素材来源 | 全收 |
| **实现机制**（缓动曲线、阻尼公式、投影矩阵、噪声、混合模式、材质分层拆解） | 数学共通，实现需转译 | **高**——转译由智能体完成 | 全收，须过第四节对照表 |
| **引擎 API**（Shader Graph、DOTween、URP、3D Mesh、Godot Tween 节点） | 不共通 | ≈0，但**思路可翻译**：全息 foil shader 的 Canvas 2D 等价物＝M7（光栅+虹彩+噪点）；Mesh 倾斜的等价物＝M6 正交投影 | 只留一句引擎注记 |

**先例即证明**：现有 M6（刚体正交投影替代 3D Mesh）与 M7（光栅/虹彩/噪点重表达全息 shader）本身就是「别处的设计思路 → p5 惯用法翻译」的产物；Balatro 纸牌摆动、Hearthstone 悬停手感等视频案例均已被社区用 Canvas/p5 复刻过，路线经过验证。

## 二、选材判定（什么视频值得蒸）

按优先级排序，且**每条必须过完整清单**：

```
P0 卡牌/桌面游戏手感类（悬停、抽牌、洗牌、翻面、打出反馈）
P1 UI juice（按钮反馈、列表动效、数字滚动、屏幕震动）
P2 材质/粒子（箔面、描边流光、消融、烟雾）——只蒸可 2D 复现的部分
P3 3D 专属（体积光、SSAO）——默认不蒸，仅当设计语言层面有启发时记一句
```

**值得蒸**（全部满足）：
- [ ] 效果可在 **2D 平面**复现（z 轴只作为视觉暗示，不需要真 3D 管线）；
- [ ] 有**可观察的拆解维度**：分层结构、驱动源（鼠标/时间/事件）、节奏（时长/缓动）；
- [ ] 聚焦**手感与设计决策**，而非引擎功能演示；
- [ ] 关键效果在视频中有**清晰的特写/慢放/分段讲解**（可锚定时码）。

**不值得蒸**（任一命中即放弃）：
- ❌ 纯引擎操作教学（Shader Graph 界面、Timeline 面板、Asset Store 插件介绍）；
- ❌ 效果本质是 3D 管线产物且无 2D 等价语义（如基于深度缓冲的折射）；
- ❌ 无拆解空间的「成果展示混剪」（只有结果没有过程，锚不到参数）。

## 四、转译对照表（核心资产，持续累积）

蒸馏时**先查此表**；表外概念先补表、后使用。每行注明首次使用的模块：

| 原方案（Unity/Godot） | p5.js 1.x/2.x 等价物 | 注意点 | 首用 |
|---|---|---|---|
| DOTween / Godot Tween | `dampApproach` + 状态字典进度驱动（M1+M2） | Tween 有确定时长，damp 是渐近——用 hoverProgress×缓动曲线补齐「确定完成时刻」语义 | M4 |
| `Time.deltaTime`（秒） | `deltaTime`（**毫秒**）→ `/1000` | 首帧可能 0/undefined，一律 `deltaTime \|\| 16.67` 兜底 | M1 |
| 全息 foil shader（虹彩/折射） | HSB `colorMode` + `blendMode(ADD)` 光栅 + `noise()` 扰动 | ADD 用完必复位 `BLEND`（硬约束 #5） | M7 |
| 3D Mesh 卡牌倾斜 / Quaternion | `applyMatrix` 正交投影（M6 刚体矩阵） | 只模拟 (x,y) 屏幕投影；sheen 用 `drawingContext` 渐变 | M6 |
| 软阴影 / shadowBlur | 分层矩形阴影（M5） | Canvas 原生 shadowBlur 是 CPU 热点，禁用于逐帧 | M5 |
| Sprite/Material tint | `cFill/cStroke` + `COLORS_RGB` 查表 | 禁 `fill('#hex')` 直书（硬约束 #4） | M8 |
| Coroutine / 异步序列 | 帧驱动状态机（`frameCount`/dt 推进） | 不用 setTimeout 拼动画（时序竞态） | M4 |
| C# Event / Godot Signal | 宿主注入点回调（对齐 M0 注入点表） | 子模块不得硬编码父场景身份（硬约束 #20 同源纪律） | M0 |
| Cinemachine 震屏/推拉 | 手写 cam 偏移（seed 随机 + 阻尼回中） | 幅度按设计基准 1280×720 给值，属「手感量」不随画布缩放 | 扩展位 |
| UI 预制体/Component | 纯函数绘制模块（M8 模式：`drawXxx(card,…)`） | 数据契约走 M0，渲染层不持业务状态 | M8 |
| 粒子系统（Shuriken/GPUParticles） | 对象池 + `rect/ellipse` 批量绘制 | 设硬顶（类推 M7 光栅 200 块），超顶先砍装饰层 | 扩展位 |

> 维护纪律：蒸馏中新遇到的引擎概念**必须先补本表**（含注意点），再进入产物正文——保证后人可复用同一条转译路径。

## 五、硬性禁令（防跑偏）

1. **不照抄引擎 API**：产物中不得残留 Quaternion/ShaderGraph 节点/Coroutine/DOTween 调用等引擎术语（引擎注记段除外，且仅一句）。
2. **不引入无 2D fallback 的 WebGL 专属方案**：p5 WebGL 后端与本套 2D 模块不兼容；需要 GPU 效果时用「shader 思路的 2D 重表达」（类推 M7）。
3. **不虚构未演示的细节**：视频里看不清/没讲的参数一律标注 `未验证`，禁止脑补默认值冒充实测值。
4. **不另起炉灶**：优先映射 M0–M8 现有模块（参数/层数级扩展优先于新模块）；确需新模块才建 M9+，且格式必须对齐 08 文档六件套。
5. **术语一致**：沿用 08 文档既有术语——「悬停进度唯一驱动源」「两遍绘制」「ADD 必复位」「手感量 vs 布局量」「降级顺序＝装饰先于反馈」。产出后应能与 08 文档**无缝拼接**。
6. **2.x 兼容标注**：新骨架若用到 08 文档第五节实证清单之外的 API，须显式标注「2.x 兼容未验证」。

## 六、性能转译规则

原方案的 GPU 假设 → Canvas 2D 成本等价，逐条换算：

| 原方案成本假设 | Canvas 2D 实际成本 | 转译纪律 |
|---|---|---|
| GPU shader 逐像素计算（近乎免费） | 每像素一次 fill 调用（昂贵） | 量化成离散图元 + **硬顶**（类推光栅 200 块），先算带内再画 |
| 实时高斯模糊（shadowBlur/Blur） | 逐帧卷积，CPU 热点 | 分层矩形近似（M5 路线） |
| 任意粒子数 | fill/rect 调用次数线性成本 | 给预算红线；降级顺序＝装饰先于反馈 |
| 全屏后处理链（bloom 等） | 全画布重绘 | 只对**核心高光**做局部 bloom 感（类推 M7 的 ADD 光带） |

降级顺序固定沿用 08 文档四节结论：呼吸漂移 → 色相循环 → 虹彩/噪点 → 阴影层数 → 缓动吸附化；交互位置反馈保留到最后。

## 七、对使用者的操作建议（维护者视角）

1. **选材渠道**：优先搜「game feel / juice / card game UI」类拆解向视频（有慢放与讲解的），混剪只当索引不当教材；Balatro、Hearthstone、Slay the Spire、Monster Train 的社区拆解是高密度素材。
2. **一鱼一蒸**：一条视频只蒸一个核心效果；同视频多效果拆成多条独立产物，时码各自锚定。
3. **验证工作流**（蒸馏 ≠ 入册）：
   - 将骨架代码丢进展厅式试验页（参照 `卡牌动效演进展厅.html` 的并排结构）与现有模块 **A/B 对照**；
   - 手感不过关 → 回第五节查是否违反禁令（最常见：引擎 API 残留、参数脑补）；
   - 通过后才并入 08 文档对应模块。
4. **入册节奏**：宁缺毋滥——并入 08 的每条都必须「完整代码+参数表+实测」，试验性内容留在本文件第九节队列。
