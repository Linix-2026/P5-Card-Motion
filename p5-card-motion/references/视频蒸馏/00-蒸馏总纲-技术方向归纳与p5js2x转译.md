## 三、五条跨视频交叉验证原则（≥2 个独立来源互证，可信度最高）

1. **视觉恒跟随不变量**（06 明示 + 02 的 rAF lerp + 09 的 DOTween 到位）：不要为每个事件写补间，让渲染状态每帧追逻辑状态。→ 本项目 M2 状态字典 + M1 damp 已是该范式，M13 把它从「悬停」扩到「拖拽换序」。
2. **输入必须归一化到对象自身空间**（02 容器中心 [-1,1] + 06 鼠标距卡心定旋转）：08 文档 M6 已用卡面半宽归一化，结论一致——抽取公共 `normalizePointer(box)`。
3. **一切动效 dt 驱动，时间缩放只乘一处**（08 SNKRX 的 slow_amount×dt 是实证）：本项目 deltaTime 硬约束自动获得子弹时间能力。
4. **多层错峰 = 廉价的「活」**（04 呼吸波叠层、01 光圈/错峰入场、05 衍射多道）：同一绘制函数按相位偏移复制 N 份，是贯穿三个引擎的通用套路；成本都线性，必须配硬顶。
5. **效果是数据组合，表现靠事件订阅**（07 多态 effects[] + 08 fx 钩子 + 04 状态参数表）：渲染模块永不直接写游戏状态——这是 M12/M14 能无侵入挂载的前提，建议写入 M0。

## 五、p5.js 2.x 转译公共内核（各篇骨架的共享底座）

> 实例模式。2.x 注意点：`p.colorMode`/`p.blendMode` 均为状态机用后复位；矩阵 API（push/pop/translate/rotate/applyMatrix）2.x 与 1.x 一致；`drawingContext` 在 2.x 仍为 CanvasRenderingContext2D（如未来版本调整需复测，标 **2.x 待复测**）。国内调试 CDN 沿用 `https://cdn.jsdmirror.com/npm/p5@2.3.3/lib/p5.min.js`（正式入仓时锁定具体小版本）。

```js
// ── kernel.js：九篇蒸馏共用的无依赖内核（约 50 行）────────────────────────
export const AnimKernel = {
  // 帧率无关阻尼（08 文档 M1；p5 2.x 实例内调用，dtMs = p.deltaTime || 16.67）
  damp(c, t, k, dtMs){ const f = 1 - Math.pow(1 - k, dtMs * 60 / 1e3); return c + (t - c) * f; },
  clamp(v, a, b){ return Math.max(a, Math.min(b, v)); },
  lerp: (a,b,t)=>a+(b-a)*t,
  // 原则②输入归一化：任意包围盒 → 中心基准 [-1,1]（M6/M10 共用）
  normalizePointer(px, py, box){ // box={x,y,w,h}
    return { nx: (px - (box.x+box.w/2)) / (box.w/2),
             ny: (py - (box.y+box.h/2)) / (box.h/2) };
  },
  // 路径采样切线（M15）：path(t∈[0,1])→{x,y}
  tangent(path, t, ...a){ const e=0.002;
    const p0=path(Math.max(0,t-e),...a), p1=path(Math.min(1,t+e),...a);
    return Math.atan2(p1.y-p0.y, p1.x-p0.x); },
};

// ── timeScale：慢动作唯一插点（原则③）。场景内一切动画只吃 effDt ───────────
function makeTimeControl(p){
  const tc = { scale:1,
    effDt(){ return (p.deltaTime||16.67) * tc.scale; },
    slow(v=0.35){ tc.scale=v; },
    update(dt){ tc.scale=AnimKernel.damp(tc.scale,1,0.06,dt); } }; // 缓回 1
  return tc;
}

// ── fx 事件总线（原则⑤）：逻辑层只发事件，表现层订阅 ──────────────────────
function makeFxBus(){
  const subs=[];
  return { on:(fn)=>subs.push(fn),
    emit:(type,payload)=>subs.forEach(fn=>fn(type,payload)) };
}
// 订阅关系示例：M14 订阅 'hit'→shake+flash+粒子；M12 由状态直接拉取；
// M7-pro/M7 不变（持续材质不适合事件，保持每帧驱动）。
```

各模块完整骨架位于同目录 01–09 各篇；入册时按《08》六件套格式（来源/依赖/代码/参数表/为什么/2.x 兼容）改写，来源列注明 BV 号与本蒸馏文件。

## 六、为 skill 创建做的准备清单

1. **建议 skill 结构**（在 08/09 之上）：
   - `references/`：08（成熟模块 M0–M8）、09（蒸馏方法论）、本目录（M9–M15 来源与骨架）；
   - `references/视频蒸馏/` 保留逐篇审计轨迹（队列状态机：待验证 → 展厅 A/B 通过 → 并入 08）；
   - `modules/`（入册代码）：kernel + M9/M12/M13/M14 先转 P0/P1；
   - `showcase/`：扩展现《卡牌动效演进展厅.html》为「技术陈列柜」，每新模块一个对照卡（原版手感 / p5 复刻）。
2. **入册顺序（依赖与性价比）**：M12 → M14 → M13（P0）→ M9 + M7-pro + M0 扩展（P1）→ M10/M11/M15 与小增强（P2）。
3. **每模块入册硬门**（沿用 09 第七节）：可运行 demo、参数表实测值（替换本批 `未验证` 参考值）、2.x 复测、性能预算（ADD 复位/硬顶/禁 shadowBlur）、reduced-motion 降级。
4. **风险登记**：
   - 02 无字幕：M10 入册前必须人工看片核对（归一化公式与多层 lerp 有简介明示，细节未核）；
   - 05 物理只取心智模型，代码里没有波动求解，文案需避免「物理精确」措辞；
   - 06 闲置圆周的振幅/速度无数值，A/B 时以 08 现有 sin 漂移为基准微调；
   - 虹彩/CRT 扫描线等强风格效果默认关闭，避免风格污染宿主项目。
5. **术语合并**：本批统一沿用 08 词汇——阻尼/进度驱动/两遍绘制/ADD 必复位/手感量 vs 布局量/装饰先于反馈；新增「逻辑/视觉双轨」「pathFn 路径抽象」「timeScale 时间缩放」「fx 事件总线」四个词，建议补入 08 GLOSSARY（如建 skill 时设术语表）。
